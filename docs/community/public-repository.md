# How the public repository was made

The public repository of Lucium starts from **one commit**. That commit holds the whole tree of the version it was made from, and no earlier history. This page says why, how the commit was made, and what was checked before it was pushed.

## Why one commit

Lucium was written in a private repository before it was opened. Its history was not written to be read: it holds working notes, reports and captures that were removed from the tree later but stay in the commits, and it weighs many times more than the sources. Publishing it would have published all of that.

So the public repository is a new one. The private repository stays the maintainer's archive. It is never a remote of the public one, and none of its branches or tags is pushed there.

What this costs: `git blame` and `git log` start at the first public commit. A change made before it is described in [CHANGELOG.md](../../CHANGELOG.md), not in a commit.

## What the first commit holds

The tree is an export of one commit of the private repository: `git archive HEAD`. It holds every tracked file, less the paths that [.gitattributes](../../.gitattributes) marks `export-ignore`: the maintainer's to-do, the working plans and a few design notes written for the maintainer alone. Nothing is rewritten on the way: every exported file has the content it had in the commit.

## The controls

`scripts/export-public.mjs` makes the export, and refuses to go on when one of these is true. Each refusal says its reason.

| Control | Refused when |
|---|---|
| The source | the working tree has a change that is not committed, or `HEAD` is not the commit that was read and approved |
| The folder | the folder that receives the export is not empty, or is inside another repository |
| Internal paths | the export holds a path that must stay private, or a key, a certificate or an environment file |
| Internal texts | a file names a home folder of a real person, a private key, a host or a tool of the maintainer, a finding of a report that is not published, or the former name of the project |
| Files outside the GPL | the logo and its icons, or the media generated by AI, are exported without the document that says their license (`TRADEMARKS.md`, `NOTICE-MEDIA.md`), or `NOTICE` does not name that document. The list `Not read` marks each of these files |
| Secrets | a complete scan of the tree finds something. Every scanner installed is run ([gitleaks](https://github.com/gitleaks/gitleaks), [TruffleHog](https://github.com/trufflesecurity/trufflehog)), and a finding counts whether a service confirms it or not. With no scanner installed, or a scanner that fails, nothing is exported |
| Identity | the author or the committer that git would write is not a GitHub `…@users.noreply.github.com` address, or commits are not signed |
| Weight | the exported files weigh more than 50 MB together (they weighed 36.8 MB in November 2026) |
| The commit | the repository that was made is not exactly one signed commit of that tree on `main`, with no remote |

The rules for paths and texts are in `src/main/public-export.ts`. The tests apply the same rules to the tracked files at every run (`src/main/public-tree.test.ts`, `src/main/former-name.test.ts`), so a file that the export would refuse is refused in a pull request first. Each refusal of the script has its own test (`src/main/public-export.test.ts`).

The rules for texts read text. A binary file (an image, a video, a font, an archive, a PDF) is not opened: the controls on its path, on its weight and the secret scanners apply to it, but nothing says what it shows or holds. The script therefore lists every binary file of the export, with its size, under `Not read`: look at each one before pushing (step 1 below).

A refused export leaves the folder empty: there is no half-made repository to push by mistake.

## The steps

```sh
# Every control, and nothing created. It prints the number of files, the weight, the hash of the tree and the binary files that were not read.
node scripts/export-public.mjs --check

# The export itself, in an empty folder outside every repository.
node scripts/export-public.mjs --commit <hash of the commit that was read> ../lucium-public
```

The script runs `git init` in the folder, without a template (no hook of the machine comes in), adds every file and makes one signed commit. It adds no remote and pushes nothing.

Then, by hand:

1. Read the commit in the new folder. `git rev-parse HEAD^{tree}` answers the hash that the script printed.
2. Run `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm lint` and `pnpm test` on the export itself.
3. Add the public repository as the only remote, and push `main`.
4. Apply the settings of the repository ([maintainers.md](maintainers.md#repository-settings-to-apply-once-github)) and go through the list of [release-process.md](release-process.md#publishing-the-repository).

## Checking it yourself

The hash of a tree depends only on the files it holds. Anyone can read the first commit of the public repository and see what it is:

```sh
git rev-list --max-parents=0 HEAD          # one commit, with no parent
git log -1 --show-signature <that commit>  # signed, with a noreply address
```

After the first commit, every change comes through a pull request, the maintainer's included ([GOVERNANCE.md](../../GOVERNANCE.md#the-rules-of-main)).
